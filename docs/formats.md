# Форматы данных

Все JSON — UTF-8. Коды пишутся единообразно: `ОК 01`, `ПК 5.1`, `МДК.05.01`, `УП.05`, `ПП.05`, `ПМ.05`.
Поля с `_` в начале — служебные (источник, заметки); программа их не печатает.

## Учебный план — `data/plans/ГРУППА.tsv`

Текст с табуляциями, первая строка может быть заголовком. Значимы строки с индексом в первом столбце:

```
Индекс  Наименование  Формы ПА  Максимальная  Самостоятельная  Обязательная  Теория  Практика  Курсовых  сем1  сем2  …
МДК.03.01  Эксплуатация …  ДЗ, Э  158  0  158  50  68  40  0  0  0  106  52  0
```
Формы — по семестрам с часами через запятую (`ДЗ, Э`), или одна форма (ставится в последний семестр), `-` — нет.
Обозначения: Э, ДЗ, З, ДР, КР, ЭК. Проверка: `tools/check_plan.py`.

## Программа воспитания — `data/vospitanie/ФАЙЛ.json`

```json
{ "title": "Рабочая программа воспитания ГБПОУ «СПЭТ» на 2026–2027 учебный год", "source_table": "Таблица 3 программы воспитания",
  "lr": {"1": "Осознанно выражающий …", "…": "…", "52": "…"},
  "ok_lr": {"ОК 01": [39, 40, 47], "…": []} }
```
В РП выводятся не все `lr`, а только объединение `ok_lr` по ОК модуля/дисциплины (`src/lr.js`); ЛР без привязки к ОК не выводятся, ключ `lr_methods["none"]` не нужен (методы — для каждого ОК). `validate` печатает «ЛР документа (N, по ОК модуля): …» — это значение для `check_docx --lr`.

### Самостоятельная работа (СР) и ЛР МДК

Необязательное поле `mdk[].sr` — СР обучающихся из тематического плана. Без него документ прежний («СР учебным планом не предусмотрена»).

```json
"sr": [
  {"sem": 4, "hours": 16, "theme": "Тема 1.2", "tasks": [["Изучение документации на датчики", 6], ["Оформление отчётов", 10]]},
  {"sem": 5, "hours": 32, "theme": "", "cp": true, "title": "Самостоятельная работа по курсовому проекту", "tasks": ["Выполнение курсового проекта"]},
  {"sem": 5, "hours": 14, "theme": "", "intro": "Подготовить рефераты по темам:", "tasks": ["тема 1", "тема 2"]}
]
```
- `sem` — индекс семестра, как в `sems[].sem`; `hours` — часы СР (не пары, в нумерацию занятий не входит);
- `tasks` — строки или `[текст, часы]`; если у всех заданий есть часы, их сумма = `hours`; `intro` — вводная строка перед заданиями;
- `theme` — номер темы (`Тема 1.2` или `1.2`): строки СР идут после занятий темы; пусто — отдельный блок в конце семестра (после курсового проекта), заголовок — `title` (по умолчанию «Внеаудиторная самостоятельная работа»);
- `cp: true` — СР на курсовой проект (в 1.3 выводится строка «в том числе на курсовой проект»).
- `validate`: сумма `sr[].hours` по МДК = «Самостоятельная» плана; если плана СР > 0, а `sr` нет — предупреждение.
- Часы СР входят в «Всего» МДК (п. 1.2, 1.3, 2.1, «Всего по МДК»), в «теор … п/р … с/р …» семестра.
- `mdk[].lr` — необязательный список номеров ЛР, если преподаватель задал их для МДК явно (вместо вывода из ОК): `"lr": [15, 38, 39]`; в документ выводятся только номера, входящие в ЛР модуля по ОК (остальные отбрасываются, `validate` предупреждает).
- Зачёт внутри названия занятия: у занятия `lessons[]` ставьте `"att": true` (в том числе для `k: "P"`) — тогда пара считается зачётной (2 ч) и отдельная строка «Промежуточная аттестация … —» не выводится.

## Учебная дисциплина (`"kind": "ud"`)

Режим для ОП, ОГСЭ, ЕН, общеобразовательных дисциплин; сборка ПМ он не затрагивает (для `kind` ≠ `ud` всё прежнее). Макет — «РП УД (Топ-50)» ГБПОУ «СПЭТ».
Команды те же: `new --kind ud`, `init`, `stages`, `next`/`import`/`fill`, `validate`, `lint`, `build`; `python3 tools/check_docx.py` сам узнаёт документ УД.

**Учебный план** — обычная строка дисциплины (`ОП.04 …`) в `data/plans/ГРУППА.tsv`; проверка `python3 tools/check_plan.py план.tsv ОП.04` (суммы, пары по 2 ч).

**КТП** — `data/ktp/ГРУППА_УД.json`, из xlsx преподавателя: `python3 -I tools/ktp_from_xlsx.py ktp.xlsx data/ktp/….json` (`--check` сверяет JSON с xlsx).
`sections[]{num,name,hours,themes[]{num,name,hours,lessons[]{n,t,h,k:"T"|"P",vid,materials,homework}}}`. Названия занятий дословно.

**ПОП-УД** — `data/pop/КОД_ОП04.json` из приложения 2 к ПОП-П: `python3 -I tools/pop_extract_ud.py приложение2.docx 2.4 ОП.04 out.json`;
проверка `python3 tools/verify_sources.py out.json приложение2.docx --plan план.tsv --fgos фгос.json` (признак УД — поле `discipline`).
Поля: `discipline, goal, place, results_intro, results{ok{КОД:{um,zn,nav}},pk{…}}, hours, sections[]{section,hours,themes[]{num,name,content[],labs[]{n,title}}}, assessment[]{kind,results[],criteria[],methods_title,methods[]}, rooms[], literature_main[], literature_add[], _cover, _ack, _notes`.
Тематика ПОП в документе не используется (занятия — по КТП); ОК и ПК дисциплины — только из `results` ПОП.

**project.json**: `kind:"ud"`, `ud:"ОП.04"` (вместо `pm`), `ktp` (путь к КТП), остальное как у ПМ (`fgos, vospitanie, plan, pop, group, year, org, people, pcc, competence, hints`).

**content.json**:
```json
{"meta": {"kind":"ud","code":"ОП.04","name":"…","total_hours":84,"exam_sem":2,"exam_label":"2 курс, 1 семестр","ok":["ОК 01"],"pk":[["ПК 2.3","…"]],
          "split_note":"подтверждение расхождения деления теория/практика КТП и плана (если есть)"},
 "ud": {"code":"ОП.04","name":"…","custom":true,"T":34,"P":50,"K":0,
        "sems":[{"sem":2,"label":"2 курс, 1 семестр","hours":84,"form":"Э"}],
        "themes":[{"num":"Тема 1.1.","name":"…","section":"Раздел 1. …","content":["перечень дидактических единиц"],"codes":"ОК 01, ОК 02; ПК 2.4",
                   "lessons":[{"k":"T","t":"название из КТП","h":2},{"k":"P","t":"…","h":2,"hw":"домашнее задание КТП"}]}],
        "sr":[]},
 "program": {"conditions":{"equipment":{"cabinet":[],"lab":[]},"software":[]},"lr_methods":{"ОК 01":"…"},"control":{"current":"устного опроса, …"},"electronic":[]},
 "fos": {"tests":[{"q":"…","options":["а","б","в","г"],"answer":1,"t":3}],"exams":{"ОП.04":{"questions":[],"tasks":["Дано: … Задание: … Результат: …"]}},"control_works":{}},
 "_done":[],"fos._parts":{}}
```
`T`/`P` в `ud` — часы из плана; занятия — из КТП (`k` T/P, 2 ч). `content` темы КТП не задаёт — init берёт названия занятий (в COMPLETENESS.md отмечается как составленное). `sr` — как у МДК (СР по плану > 0).
**Нет КТП преподавателя** — занятия составляет автор по ПОП и плану: `python3 -I tools/ktp_from_pop.py data/pop/….json data/plans/….tsv ОП.01 data/ktp/….json [--spec spec.json]` (темы и практические работы — из ПОП дословно, названия теоретических занятий и число пар — по `--spec` или поровну; в файле `"_generated": true`). Дальше всё как с КТП (`new --ktp …`); `init` пишет `content._notes` «КТП преподавателя отсутствует — занятия составлены нами; заменить при получении КТП», а в COMPLETENESS.md это отмечается явно. СР по плану > 0, а в ПОП тематика «определяется образовательной организацией» — задания `ud.sr` составляются по темам и тоже отмечаются как составленные.
**ПООП СПО** (приложение «II.N» к программе СПО, формат 2021: нет разделов, нет цели дисциплины, одна строка результатов на все коды, практические работы общим списком):
`python3 -I tools/pop_extract_ud.py poop_spo.docx II.7 ОП.04 data/pop/09.02.06_OP04.json --labs "2=1-6,3=7-10" [--ok-map "ОК 09=ОК 02,ОК 10=ОК 09"] [--note "причина замены прежнего файла"]`
(.doc → .docx — `soffice --convert-to docx`); `--labs` относит работы к темам, `--ok-map` — коды ОК ПООП (ФГОС 2016) → ФГОС группы (исходные коды сохраняются в `codes_poop`, замена — в `_ok_map`). `sections[]` — один безымянный раздел (`section: ""`), `goal`/`results_intro` пусты (в п. 1.2 остаётся макетная фраза), `rooms` может не содержать кабинета (в 3.1 — только лаборатория). Часы ПООП в РП не используются.
КТП по ПООП с названиями занятий из КТП преподавателя: `ktp_from_pop.py … --spec spec.json`, где spec с ключом `lessons` задаёт занятия по темам (`ktp` — номер занятия КТП преподавателя, `covers` — пункты содержания ПООП, `work`/`pairs` — работы ПООП и число пар; см. docstring); занятия из КТП помечены `src: "ktp"`, validate проверяет `covers` вместо «фрагмент содержания».
ПОП «Профессионалитет» (приложение 2 к ПООП): `pop_extract_ud.py … --item-per-paragraph` (пункты — абзацы ячейки); одна строка таблицы результатов на несколько кодов (`ОК 03, ОК 06, ОК 09, ПК 2.3`) — `results_shared: true`, в документе одна общая строка; практические занятия без номеров нумеруются по порядку; литература без нумерации переносится абзацами.
Необязательные поля `program`: `pr_criteria5` (критерий оценки «5» за практическую работу, если дисциплина не про программирование), `test_where` (где проводится тестирование).
Этапы (`stages`): `codes` (ОК/ПК по темам), `program` (оснащение, ПО, формы контроля, методы ЛР), `tests:КОД:1…3`, `exams`: `exam:КОД:1…3` (по 20; 60 вопросов, 60 заданий «Дано … Результат …»), `cw:КОД` — только при форме ДР/КР.
Файл ответа этапа: `answers/` по имени этапа (`:` → `_`). Селфтест `tools/selftest.js` проверяет и проекты УД.
