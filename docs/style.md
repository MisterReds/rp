# Как писать тексты (образцы — из `examples/`)

Общее: официально-деловой стиль, термины специальности, конкретика вместо общих слов. Каждая строка документа отвечает на вопрос
«что именно изучается / делается / проверяется». Нет «и т. д.», «…», «различные», «основные вопросы», «повторение материала».

## 1. Названия теоретических занятий (этап themes)

Берутся из содержания темы ПОП по порядку. Одна строка содержания = одно-два занятия; мелкие соседние единицы объединяются.

Тема ПОП: «Тема 5.1.1. Основы проектирования информационных систем». Содержание: «Основные понятия и определения ИС. Жизненный цикл
информационных систем», «Организация и методы сбора информации. Анализ предметной области. Основные понятия системного и структурного анализа.», …

| Хорошо | Плохо | Почему плохо |
|---|---|---|
| Основные понятия и определения ИС. Жизненный цикл информационных систем | Основы проектирования информационных систем | повторяет название темы |
| Организация и методы сбора информации. Анализ предметной области. Системный и структурный анализ | Основы проектирования ИС (часть 2) | «часть» — деление делает программа |
| Постановка задачи обработки информации. Виды, алгоритмы и процедуры обработки информации | Лекция 3. Обработка информации | «Лекция N» не пишется |
| — | Повторение и обобщение материала | не дидактическая единица |
| — | Современные тенденции в области ИС | нет в содержании ПОП |

Коды: `"ПК 5.1, ПК 5.2, ПК 5.7; ОК 01, ОК 02, ОК 04, ОК 09"` — ПК, которые тема реально формирует (сверь со словами ПК), 1–5 ОК.

## 2. Курсовой проект (этап course)

Тема — объект + задача + условие: «Проектирование локальной сети офиса на 40 рабочих мест с сегментацией VLAN».
Плохо: «Компьютерные сети», «Разработка проекта» — нет объекта и задачи.
Этапы — по 2 ч: «Выдача задания. Анализ предметной области», «Разработка структурной схемы», …, «Оформление пояснительной записки», «Защита».

## 3. Учебная практика (этап up)

`name` — вид работ ПОП посимвольно. Задание — действие + объект + условие, 2–8 ч:

| Хорошо | Плохо |
|---|---|
| Инструктаж по охране труда и пожарной безопасности. Организация рабочего места (2) | Вводное занятие (2) |
| Обследование предметной области, интервьюирование заказчика (4) | Работа с заказчиком (4) |
| Монтаж и тестирование витой пары категории 5e, оконцовка розеток и патч-панели (6) | Практическая работа по кабелям (6) |
| Оформление отчёта по учебной практике. Дифференцированный зачёт (2) — только если ДЗ по плану | Итоговое занятие (2) |

## 4. Производственная практика (этап pp)

День = 6 ч работы в профильной организации, а не учебное упражнение.

| Хорошо | Плохо |
|---|---|
| Оформление на предприятии, инструктаж по охране труда, ознакомление с информационными системами организации | Первый день |
| Сбор исходных данных и требований пользователей отдела продаж | Сбор данных |
| Оформление отчёта по практике | Защита отчёта, дифференцированный зачёт ← **запрещено** |

## 5. Оснащение и методы ЛР (этап program)

- Кабинет — формула шаблона + пособия **по модулю**: «комплект учебно-наглядных пособий: схемы жизненного цикла ИС, нотаций IDEF0 и UML, структуры технической документации по ЕСПД и ГОСТ 34».
- Лаборатория/мастерская — то, на чём делаются практические работы: «рабочие места обучающихся с ПК и доступом в сеть», «коммутаторы управляемые уровня 2/3», «стенд IP-телефонии».
- ПО — по работам: СУБД, среда разработки, система контроля версий, эмулятор сети; без версий и цен.
- `lr_methods["ОК 01"]` — «МДК.05.01–МДК.05.03 — практические работы с выбором и обоснованием проектных решений; УП.05 — выполнение комплексных заданий».
  Для каждого ОК — свой текст; для `none` — кураторские часы, воспитательные мероприятия, характеристика руководителя практики.

## 6. Тесты (этап tests)

```json
{"q": "Какая модель жизненного цикла предполагает последовательное выполнение этапов без возврата?",
 "options": ["спиральная", "каскадная", "инкрементная", "итерационная"], "answer": 1, "t": 1}
```
- Варианты — однородные (все — названия моделей), одной длины и формы.
- Плохо: правильный вариант длиннее и подробнее остальных; «все ответы верны»; вариант-шутка; два верных варианта; вопрос «Что такое X?» с ответом «X — это …» из слов вопроса.
- Ключи: при 20 вопросах по 4–6 на каждую букву.

## 7. Вопросы к экзамену (этап exam)

Вопрос — дидактическая единица темы, по порядку тем: «Модели жизненного цикла ИС: каскадная, спиральная, итерационная. Сравнение и область применения».
Плохо: «Тема 1.1», «Основы проектирования» — название темы, а не вопрос.

## 8. Практические задачи к экзамену (этап exam)

Действие + исходные данные + результат:
- Хорошо: «Определить корневой мост STP. SW1 — приоритет 32768, MAC 0019.aa00.0001; SW2 — 4096, MAC 0019.aa00.0005; SW3 — 4096, MAC 0019.aa00.0003. Обосновать ответ.»
- Плохо: «Настроить STP на коммутаторах.» — нет данных, нечего проверять.

## 9. Контрольная работа (этап cw)

4 варианта одной структуры, разные числа/объекты; `answer` — эталон с числами (пересчитан). Задание 1 — теоретическое, 2–4 — расчётные/аналитические.

## 10. Экзамен по модулю (этап module_exam)

- Части: «практическое задание: проектирование и разработка модуля ИС» (ПК 5.1–5.4, 120 мин), «практическое задание: тестирование, документирование и оценка ИС» (ПК 5.5–5.7, 60 мин).
- Вариант: `data` — исходные данные стенда/предметной области; `tasks` — задания с ПК; `examiner_note` — вносимые неисправности (только для экзаменатора).
- Оценочный лист: наблюдаемые критерии («Структура базы данных спроектирована, нормализована до 3НФ», 8 баллов), по каждой ПК, сумма 100.
- Протокол проверки: «Запуск приложения | запуск по руководству | приложение запускается без ошибок».
