# Правила документа (коротко, без исключений)

Источник требований: шаблон РП ПМ ГБПОУ «СПЭТ», методический отдел, ФГОС, ПОП. Подробности и обоснования — `ИНСТРУКЦИЯ.md`, часть 1.
Каждое правило проверяется командой, указанной в скобках; правила без команды проверяет `reviewer`.

## Форма
1. РП и ФОС — **один** .docx; ФОС — раздел 5. Структура и формулировки — по шаблону СПЭТ; собирает только `build`.
2. Нет оглавления, таблицы «Трудоёмкость освоения модуля», сноски под таблицей структуры, таблицы «Цифровые инструменты». (`check_docx`)
3. Оборот титула: ФГОС с реквизитами приказа и регистрации в Минюсте; компетенция чемпионата «Профессионалы». **Никакого WorldSkills / «Молодые профессионалы».** (`lint`, `check_docx`)

## Источники
4. ОК, ВД, ПК — дословно из ФГОС (ОК — по ФГОС/ПОП конкретной специальности: где-то 01–09, где-то 01–11). (`verify_sources`)
5. Из ПОП дословно: разделы, номера и названия тем, содержание тем, лабораторные/практические работы, виды работ практик,
   таблица «Код ОК, ПК | Уметь | Знать | Владеть навыками» (или «опыт/уметь/знать»), критерии и методы оценки, помещения, литература. (`verify_sources --cover`)
6. Темы — это не занятия: тема ПОП с её содержанием идёт строкой-заголовком, под ней — занятия.
7. Часы — **только** из учебного плана группы, не из ПОП. (`check_plan`, `validate`)
8. Все ЛР действующей программы воспитания (СПЭТ 2026–2027 — 52 ЛР), коды ЛР — через таблицу соответствия ОК–ЛР. (`check_docx`)
   ПМ, шедший и в прошлом учебном году (семестры плана приходятся на 2025/2026 и 2026/2027), — сначала ЛР прошлого года «(2025/2026 учебный год)», затем текущего, в 1.1.4 и 4.2: `vospitanie_prev` в project.json. Для УГС 09.00.00 — `data/vospitanie/spet_2025-2026_09.00.00.json`. ПМ целиком в прошлых годах — вопрос человеку.

## Тематический план (раздел 2)
9. Каждая строка занятия МДК и учебной практики — пара 2 ч. Производственная практика — дни по 6 ч. (`validate`)
10. Занятия нумеруются сквозь по МДК: 1, 2, 3 … (теория и практика вместе, с 1 в каждом МДК). (`check_docx`)
11. Практическое занятие — «Практическая работа № N. Название работы ПОП», N сквозной внутри МДК, **каждая пара — свой номер**;
    работа ПОП на несколько пар → «(часть 1)», «(часть 2)» с разными номерами. (`check_docx`)
12. Теоретическое занятие — только номер и название, без «Лекция», «Занятие», «Часть». (`lint`)
13. Строки «В том числе практических занятий» не пишутся. Тема, не вошедшая в семестр, продолжается в следующем.
14. Самостоятельная работа 0 ч → «учебным планом не предусмотрена»; СР > 0 — `mdk[].sr` (формат — `docs/formats.md`), сумма = «Самостоятельная» плана, часы входят в «Всего» МДК.
14б. **Зачёт (ДЗ, З) — последняя пара семестра и входит в КТП** (МДК и УП): строка «N. Дифференцированный зачёт» на 2 ч в часах МДК/практики; экзамен — в сессию, строкой «Промежуточная аттестация в форме экзамена». (`validate`)
14а. Содержание УП и ПП — таблица по образцу программ практик техникума (`docs/practice_format.md`): «Раздел N. … | Содержание | часы | коды», темы или пункты со своими часами, сквозная нумерация пунктов, «ИТОГО». Пункты УП кратны 2 ч, ПП — 6 ч; на пары не делятся.

## Аттестация
15. Формы — конкретно: «в форме экзамена (2 курс, 1 семестр)». Не «в формах, установленных учебным планом». (`check_docx`)
16. **Производственная практика — без зачёта**: по окончании — отчёт по практике (`forms_override: {"ПП.0N": null}`). (`lint`, `check_docx`)
17. **Портфолио нет нигде.** Экзамен по модулю — практические задания по всем ПК. (`lint`, `check_docx`)

## ФОС (раздел 5)
18. По элементам: МДК.01 по семестрам → МДК.02 по семестрам → … → УП → ПП → экзамен по модулю. Не «по видам контроля вперемешку».
19. **Минимум 60 — по 2 на каждого обучающегося (набор ~30 человек):** 60 тестовых вопросов на каждый МДК; 60 теоретических вопросов и 60 практических заданий на каждую промежуточную аттестацию МДК (экзамен, дифференцированный зачёт, зачёт); 60 вопросов к зачёту по учебной практике. (`validate`, этапы частями по 20)
19а. Тест: 4 варианта, один верный, верные распределены по а–г, правильный вариант не выделяется длиной, ключ. Практические задания одного типа допустимы только с разными исходными данными. (этап `tests`, `lint`)
20. Контрольная работа: ≥ 3–4 варианта с эталонами. Экзамен по модулю: ≥ 4 варианта, оценочный лист на 100 баллов по каждой ПК. (этапы `cw`, `module_exam`)

## Работа агентов
21. Не выдумывать: темы, работы, ПК/ОК/ЛР, литературу, номера ГОСТ и приказов, модели оборудования. Нет данных — вопрос человеку или `[проверить]`.
22. Никаких служебных фраз нейросети, английского текста, «и т. д.», «…» в документе. (`lint`)

## Учебная дисциплина (`kind: ud`, `docs/formats.md`)
23. Структура и формулировки — по макету РП УД («Топ-50»): титул, оборот, разделы 1–5. Не включаются: таблица «Цифровые инструменты» (правило 2), WorldSkills (правило 3), п. 2.3 и абзацы «только для ОВЗ». (`check_docx`)
24. Часы — из учебного плана; занятия, их порядок, названия и виды — из КТП преподавателя дословно (занятие = пара 2 ч, нумерация сквозная, практические работы № 1, 2, 3 …). Деление «теория/практика» КТП ≠ плана — вопрос человеку (`meta.split_note`). (`validate`, `check_docx`)
25. ДЗ/З — последняя пара семестра, входит в часы; экзамен (Э) — в сессию, в часы занятий не входит. ОК дисциплины — только из приложения ПООП (`results` ПОП-УД); ЛР — все (52), методы — по ОК дисциплины. (`validate`, `check_docx`)
26. ФОС: тест ≥ 60 вопросов с ключом; на каждую аттестацию ≥ 60 вопросов и ≥ 60 заданий «Дано … Результат …» с проверяемым верным результатом; контрольная ≥ 3–4 варианта — только если форма ДР/КР. Разделы ФОС — как в макете (5.1.1–5.2.4), не предусмотренные планом пишутся «не предусмотрено». (`validate`, `lint`, `check_docx`)
