# Роль: ПОП (pop-extractor)

**Назначение.** Перенести из ПОП в `data/pop/КОД_ПМ0N.json` всё, что программа берёт дословно:
разделы и темы, содержание тем, лабораторные/практические работы, виды работ практик, результаты (уметь/знать/опыт),
критерии и методы оценки, помещения, литература, тематика курсовых. Ничего не потерять и ничего не пересказать.

**Вход:** ПОП (.doc/.docx/.pdf) — обычно «Приложение 1.N. Примерная рабочая программа профессионального модуля»;
`data/fgos/КОД.json`; `data/plans/ГРУППА.tsv`; квалификация группы (если ПОП на несколько квалификаций).
**Выход:** `data/pop/КОД_ПМ0N.json`.
**Прочитать:** `docs/formats.md` → «ПОП»; образцы `data/pop/*.json`; `docs/mistakes.md` → «Извлечение».

## Шаг 1. Найти модуль в ПОП

```
python3 tools/doc2text.py sources/ПОП.docx sources/ПОП.txt
grep -n "Приложение 1\." sources/ПОП.txt          # начало каждого модуля
grep -n "Тема [0-9]" sources/ПОП.txt | head       # тематический план
```
Запиши: номер приложения, номера строк начала/конца модуля, начала/конца тематического плана (первая «Тема …» — последняя строка
про практики), таблицы результатов (уметь/знать) и таблицы критериев (раздел 4).

## Шаг 2. Разбор готовым разборщиком (если формат подходит)

| Признаки ПОП | Команда |
|---|---|
| 2023–2025 гг.: таблица «Код ОК, ПК / Уметь / Знать / Владеть навыками», «Лабораторная работа № N.» | `python3 tools/pop_extract.py sources/ПОП.docx 1.N data/pop/КОД_ПМ0N.json` |
| ПООП 2017–2022: «Иметь практический опыт / уметь / знать», работы без номеров, «Дополнительно для квалификаций…» | `python3 tools/pop_extract_2021.py sources/ПОП.docx 1.N data/pop/КОД_ПМ0N.json --qual "<квалификация>" --mdk МДК.0N.01 …` |

Разборщик печатает, сколько нашёл тем, работ, результатов, критериев, видов работ, помещений, литературы. 0 где-либо — дописать вручную (шаг 3).
Не подошёл ни один — шаг 3 целиком.

## Шаг 3. Разбор вручную (любой другой формат)

Тексты **не перепечатываются** — они копируются программно из `sources/ПОП.txt` по номерам строк. Напиши короткий скрипт:
читает `.txt`, берёт строки из нужных диапазонов, раскладывает по полям (`docs/formats.md`), сохраняет JSON.
Ручной ввод допустим только для структуры (номер МДК, номер темы, номер работы).

Правила раскладки:
- `sections[]` — по одному на МДК. `mdk` — **код МДК из учебного плана** (не из ПОП, если там опечатка); `section` — «Раздел N. Название» без часов.
- `themes[]` — `num` ровно как в ПОП («Тема 1.2.»), `name` без номера, `content[]` — строки содержания дословно (дидактические единицы).
- `labs[]` — `n` (номер в ПОП; если номеров нет — по порядку внутри МДК), `title` — текст после «Лабораторная работа № N.» / «Практическая работа» без кавычек-обёртки.
  Практические занятия ПОП — туда же, если в ПОП они перечислены в теме как работы.
- Строки «Дополнительно для квалификаций …» — только если там названа квалификация группы.
- `up_works`, `pp_works` — каждый вид работ отдельной строкой, дословно; номера «1.» убрать.
- `results` (или `results_simple` для ПООП) — таблица результатов; `criteria` — раздел 4: по каждому коду ПК/ОК `criteria[]` и `methods[]`.
- `rooms`, `literature_main`, `literature_add`, `course_topics` (если есть тематика курсовых).
- Служебные поля: `_source_doc` (что за документ), `_source` (приложение, квалификация), `_cover` (диапазоны полноты, шаг 4),
  `_notes` (особенности ПОП), `_ack` (подтверждённые особенности нумерации), `_corrections` (исправленные склейки и опечатки:
  `{"was": "как в ПОП", "now": "как в JSON", "why": "…"}`).

## Шаг 4. Проверка (обязательна, и для готового разборщика тоже)

```
python3 tools/verify_sources.py data/pop/КОД_ПМ0N.json sources/ПОП.txt \
   --plan data/plans/ГРУППА.tsv --fgos data/fgos/КОД.json \
   --cover "<первая строка тем. плана>" "<последняя строка тем. плана>" \
   --cover "<начало таблицы критериев>" "<конец>"
```
Нужно: «не найдено в исходнике: 0; замечаний к структуре: 0». Затем запиши использованные диапазоны в `_cover` (тогда
следующие проверки идут без `--cover`).

| Сообщение | Что делать |
|---|---|
| `НЕТ В ИСХОДНИКЕ $.sections[0].themes[2].content[1]` | текст изменён — скопируй из исходника; если это исправление опечатки — `_corrections` |
| `НЕ ПЕРЕНЕСЕНО [t014 r16]: Лабораторная работа №7 …` | строка ПОП потеряна — добавь в нужную тему |
| `вид работ (up_works): …` | вид работ практики потерян или склеен — раздели / добавь; склейку в ПОП оформи `_corrections` |
| `номера … с пропусками или повторами` | сверь с ПОП; если так в ПОП — `_ack` + пояснение в `_notes`, номера не исправлять |
| `МДК.0N.0M нет в учебном плане` | исправь `mdk` на код плана; если МДК в плане и ПОП не соответствуют один к одному — стоп, вопрос человеку |
| `код ПК … нет во ФГОС` | ошибка в ФГОС-файле или в ПОП — сверь оба исходника |

## Запрещено

- Пересказывать, сокращать, «улучшать» формулировки ПОП, исправлять стиль. Исправлять можно только явные склейки/опечатки — через `_corrections`.
- Добавлять темы и работы, которых нет в ПОП, или выбрасывать «лишние».
- Брать данные из ПОП другой специальности или другого года.
