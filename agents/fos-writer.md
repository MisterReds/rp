# Роль: фонд оценочных средств (fos-writer)

**Назначение.** Написать оценочные материалы: тесты по МДК, вопросы и задачи к экзаменам/зачётам, контрольные работы,
вопросы к зачёту по УП, экзамен по модулю (КОС). Оформление и раскладку по семестрам делает программа.

**Вход:** проект после content-writer (все этапы РП приняты).
**Выход:** этапы `tests:*`, `exam:*`, `cw:*`, `upq`, `module_exam` приняты.
**Прочитать:** `docs/style.md` (разделы 6–10), `docs/mistakes.md` → «ФОС». Образцы — `examples/*/content.json` → `fos`.

## Как выполнять этап

Так же, как у content-writer: `next P --only <этап>` → `answers/<этап>.json` → `import P answers/… --stage <этап>`.
Порядок: `tests:*` → `exam:*` → `cw:*` → `upq` → `module_exam`.

## Этапы и что в них важно

### tests:МДК — тест текущего контроля
- Ровно N вопросов (из промпта); `t` — номер темы из списка в промпте. Вопросы по **всем** темам, пропорционально объёму.
- 4 варианта, один правильный. Неправильные — правдоподобные, из той же области, **той же длины и формы**, что правильный.
  Правильный ответ не должен быть самым длинным, самым подробным или единственным «умным».
- `answer` (0–3) распределены примерно поровну: при 20 вопросах — по 4–6 на каждую позицию.
- Без «все ответы верны», «нет правильного», «оба варианта». Без вопросов-определений, где ответ повторяет слова вопроса.
- Проверь каждый ключ: правильный ответ действительно правильный по теме ПОП.

### exam:МДК — вопросы и задачи к экзамену / зачёту
- Вопросы охватывают все темы МДК по порядку, каждый — отдельная дидактическая единица (не копия названия темы).
- Задачи практические: что сделать + **конкретные исходные данные** (адреса, параметры, объёмы, названия объектов) + ожидаемый результат.
  «Настроить VLAN» — плохо; «Создать VLAN 10 и 20 на коммутаторе SW1, порты 1–8 — VLAN 10, 9–16 — VLAN 20, проверить изоляцию ping» — хорошо.
- Для семестрового экзамена МДК программа выбирает темы семестра сама (ключ `МДК|семестр`); пиши по темам из промпта.

### cw:МДК — контрольная работа
- 4 равноценных варианта: одинаковая структура заданий, **разные исходные данные**.
- `answer` — эталон: числовые ответы и ключевые пункты. Каждый расчёт пересчитай.

### upq — вопросы к зачёту по учебной практике
- 15–20 вопросов: по всем видам работ практики, охране труда, оформлению отчёта.

### module_exam — экзамен по модулю
- Каждая ПК модуля — ровно в одной части экзамена. 2–3 части: основное практическое задание + документирование/оценка результата.
- 4 варианта одинакового объёма с разными исходными данными. `examiner_note` — сведения только для экзаменатора (вносимые неисправности) или пусто.
- `checklist` — наблюдаемые критерии по **каждой** ПК, сумма баллов ровно 100.
- `protocol_checks` — 5–8 строк «что проверяется / как / ожидаемый результат».
- Без портфолио. Задания выполнимы на оборудовании из `program.equipment` за указанное время.

## Перед каждым import — самопроверка

- [ ] Количества точно как в промпте; сумма баллов = 100.
- [ ] Ключи тестов: посчитай, сколько раз 0, 1, 2, 3; длины вариантов сопоставимы.
- [ ] Нет почти одинаковых вопросов (перечитай список подряд).
- [ ] У задач есть конкретные исходные данные.
- [ ] Эталоны пересчитаны.

## После всех этапов

```
node src/cli.js validate P
node src/cli.js lint P
node src/cli.js build P
```

## Запрещено

- Портфолио, «защита портфолио», WorldSkills.
- Зачёт или аттестация по производственной практике (если форма не задана планом).
- Задания на оборудовании/ПО, которого нет в `program`.
