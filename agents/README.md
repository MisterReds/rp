# Процесс: от исходных документов до готовой программы

## Схема

```
 человек даёт: учебный план (.xlsx), ФГОС, ПОП, программа воспитания, номер ПМ, группа, [готовая программа МДК]
                 │
         ┌───────┴────────────── orchestrator ──────────────────────────────┐
         │  1. Приём: папка проекта, sources/, STATUS.md                      │
         │                                                                    │
         │  2. Извлечение (можно параллельно, каждое — своим исполнителем):   │
         │     plan-reader ─► data/plans/ГРУППА.tsv                           │
         │     fgos-extractor ─► data/fgos/КОД.json                           │
         │     pop-extractor ─► data/pop/КОД_ПМ0N.json   (после fgos)         │
         │     vospitanie-extractor ─► data/vospitanie/ФАЙЛ.json              │
         │     mdk-importer ─► custom-МДК (только если человек велел)          │
         │                                                                    │
         │  3. Каркас: new → init (делает координатор, только программа)      │
         │                                                                    │
         │  4. Наполнение:                                                    │
         │     content-writer ─► themes, course, up, pp, program              │
         │     fos-writer ─► tests, exam, cw, upq, module_exam                │
         │                                                                    │
         │  5. Сборка: validate → lint → build                                │
         │  6. reviewer (независимо) ─► REVIEW.md: ПРИНЯТО / НА ДОРАБОТКУ     │
         │  7. Выдача .docx + список «проверить человеку»                     │
         └────────────────────────────────────────────────────────────────────┘
```

## Роли

| Роль | Карточка | Вход | Выход | Готово, когда |
|---|---|---|---|---|
| Координатор | `orchestrator.md` | запрос человека, файлы | проект, STATUS.md, .docx | reviewer: ПРИНЯТО |
| Учебный план | `plan-reader.md` | .xlsx / таблица | `data/plans/ГРУППА.tsv` | `init` без замечаний по плану, суммы сходятся |
| ФГОС | `fgos-extractor.md` | ФГОС (.pdf/.docx) или ПОП | `data/fgos/КОД.json` | `verify_sources.py` — 0 расхождений |
| ПОП | `pop-extractor.md` | ПОП (.doc/.docx/.pdf) | `data/pop/КОД_ПМ0N.json` | `verify_sources.py --plan --fgos` — 0 |
| Программа воспитания | `vospitanie-extractor.md` | программа воспитания | `data/vospitanie/ФАЙЛ.json` | `verify_sources.py` — 0, 52 (или сколько есть) ЛР |
| Перенос МДК | `mdk-importer.md` | готовая РП с этим МДК | `custom`-МДК в content.json | часы = план, `validate` — 0 |
| Наполнение РП | `content-writer.md` | каркас content.json | этапы themes, course, up, pp, program | `import` принял каждый этап |
| ФОС | `fos-writer.md` | content.json после РП | этапы tests, exam, cw, upq, module_exam | `import` принял каждый этап |
| Проверяющий | `reviewer.md` | .docx, content.json, исходники | `REVIEW.md` | вердикт вынесен |

Параллельно можно: plan-reader, fgos-extractor, vospitanie-extractor; pop-extractor — после fgos-extractor (сверяет коды ПК).
content-writer — после init; fos-writer — после content-writer (тесты и билеты опираются на занятия). reviewer — последним.

## Папка проекта

```
projects/PM05_OP-2301is/
  project.json         паспорт (создаёт new, реквизиты — координатор)
  content.json         наполнение (создаёт init, пишут только через import/fill)
  STATUS.md            журнал: что сделано, кем, что открыто (шаблон — templates/STATUS.md)
  REVIEW.md            заключение проверяющего (шаблон — templates/REVIEW.md)
  sources/             копии исходников и их .txt из tools/doc2text.py
  answers/             ответы этапов: themes_МДК.05.01.json, tests_МДК.05.01.json …
  prompt_next.md       промпт текущего этапа (создаёт next)
```

Исходники человека никогда не правятся — работа идёт с копиями в `sources/`.

## Передача работы между ролями

1. Координатор ставит задачу исполнителю одной фразой + путь к карточке + пути к входным файлам и папке проекта.
   Шаблон: «Ты — <роль>. Прочитай agents/<роль>.md и AGENTS.md. Проект: projects/X. Вход: …. Верни: что сделано, результат проверок, открытые вопросы.»
2. Исполнитель делает только свою роль, проверяет результат командами из карточки и дописывает в `STATUS.md` строку своего раздела.
3. Исполнитель возвращает координатору: файлы, вывод проверочных команд (последние строки), список «спросить человека».
4. Координатор не принимает результат без вывода проверочной команды с нулём ошибок.

## Наполнение: два режима

- **Агент сам пишет ответы (без API):** `node src/cli.js next P --only <этап>` → прочитать `prompt_next.md` →
  записать JSON в `answers/<этап>.json` (двоеточие в имени заменить на `_`) → `node src/cli.js import P answers/<этап>.json --stage <этап>`.
  Если `import` вернул замечания — исправить **весь** JSON по каждому замечанию и импортировать снова.
- **Через API модели:** `node src/cli.js fill P [--only <этап>]` — программа сама отправляет промпты и возвращает модели замечания (до 4 попыток).

В обоих режимах ответ записывается в content.json **только** через проверку этапа. Править content.json руками можно только
в случаях, перечисленных в карточках (перераспределение пар, custom-МДК), и после этого обязательно `validate` + `lint`.

## Стоп: когда остановиться и спросить человека

- Нет ПОП, ФГОС, учебного плана или программы воспитания, а их нельзя взять из присланного.
- В плане нет нужного ПМ, или часы МДК нечётные, или суммы плана не сходятся.
- Коды МДК плана не совпадают с ПОП, и соответствие неочевидно (не просто опечатка).
- В ПОП несколько квалификаций / вариантов модуля, а какая у группы — неизвестно.
- Человек требует перенести МДК из готовой программы, но файла нет.
- Этап не принят после 4 попыток, и причина не в тексте ответа (а в данных или правилах).
- Проверяющий дважды вернул «НА ДОРАБОТКУ» по одному и тому же пункту.

Вопрос человеку — один, конкретный, с вариантами ответа. Всё, что не блокирует, делается дальше; вопрос записывается в STATUS.md.

## Что никогда не делает ни одна роль

- Не придумывает темы, работы, виды работ, ПК, ОК, ЛР, литературу, реквизиты приказов.
- Не меняет часы плана и не «округляет» их.
- Не собирает и не правит .docx вручную.
- Не пишет «портфолио», «WorldSkills», таблицу «Цифровые инструменты», зачёт по производственной практике.
- Не выдаёт результат без проверочных команд.
