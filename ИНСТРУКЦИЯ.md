# Инструкция: рабочая программа профессионального модуля с фондом оценочных средств

Инструкция для преподавателей ГБПОУ «СПЭТ» и для нейросетей, которые помогают их составлять. Состоит из четырёх частей:

- **Часть 1** — каким должен быть документ: требования и правила.
- **Часть 2** — как составить его вручную.
- **Часть 3** — как пользоваться программой `rpgen`, которая делает всё автоматически.
- **Часть 4** — проверочный лист перед сдачей.

Обозначения:

- **[норматив]** — требование федеральных документов.
- **[СПЭТ]** — внутреннее требование техникума: его устанавливает методический отдел.
- **[практика]** — сложившаяся практика оформления. Её можно менять по согласованию с методистом.

---

## Часть 1. Требования к документу

### 1.1. Что сдаётся

1. **[СПЭТ]** Рабочая программа профессионального модуля (РП ПМ) и фонд оценочных средств (ФОС) сдаются **одним файлом .docx**. ФОС входит в программу как «Приложение 1. Фонд оценочных средств по профессиональному модулю». Отдельные файлы не принимаются.
2. **[СПЭТ]** Файл сдаётся в методический отдел. После проверки программа одобряется в «Сетевом городе».
3. **[СПЭТ]** В программе обязательно есть **личностные результаты (ЛР)** по действующей рабочей программе воспитания техникума. Для 2026–2027 учебного года — 52 ЛР; соответствие ОК и ЛР задано таблицей 3 программы воспитания.

### 1.2. Нормативная основа

Для СПО программу составляют по таким документам:

- **ФГОС СПО по специальности.** Для 09.02.06 — приказ Минпросвещения России от 10.07.2023 № 519. Из него берутся:
  - перечень ОК 01–09;
  - виды деятельности и ПК — **дословно**, по таблице № 2.
- **Примерная образовательная программа (ПОП)** из реестра. Её регистрационный номер указывается на обороте титула.
- **Профессиональный стандарт.** Для 09.02.06 — 06.026 «Системный администратор информационно-коммуникационных систем», приказ Минтруда России № 680н от 29.09.2020.
- **Порядок организации образовательной деятельности по программам СПО** — приказ Минпросвещения России от 24.08.2022 № 762.
- **Положение о практической подготовке** — приказ № 885/390 от 05.08.2020.
- **Рабочая программа воспитания техникума.**
- **Учебный план группы.** Часы и формы аттестации переносятся из него **без изменений**.

ГОСТы содержание программы не регламентируют. Применяются только к оформлению: ГОСТ Р 7.0.97-2016 (реквизиты документа) и ГОСТ Р 7.0.100-2018 (библиографическое описание). Если программа ссылается на отраслевые ГОСТы (например, ГОСТ Р 53246-2008 по СКС), их номера и названия нужно проверить.

### 1.4. Правила тематического плана (п. 2.2) [СПЭТ]

Это главное, на что смотрит методист.

1. **Каждое занятие — отдельная строка на 2 часа (пара).** Правило действует для теоретических и практических занятий всех МДК и для учебной практики.
2. **Производственная практика расписывается по дням: одна строка — 6 часов.**
3. **Длинная работа делится на части.** Если на одну практическую работу отведено 4–6 ч, она занимает 2–3 строки: «Настройка VLAN (часть 1)», «(часть 2)».
4. **Нумерация занятий** — просто число: «1.», «2.», без слов «Занятие» и «Практическое занятие». Номер сквозной внутри одного МДК: теория и практика по порядку проведения. **В каждом новом МДК счёт начинается с 1.** Учебная и производственная практики нумеруются каждая со своей единицы. Практические пары дополнительно нумеруются «Практическая работа № N» — отдельный счёт внутри МДК, чтобы было видно число практических и теоретических занятий.
5. **Темы устроены одинаково:**
   - в левом столбце — «Тема 1.1. Название» и строка «Всего: N ч»;
   - первая строка темы — «Содержание учебного материала» и **краткое содержание темы** в 2–3 предложения (вопросы темы). Краткое содержание — это не список названий занятий и не повтор одного из них;
   - ниже — теоретические занятия по 2 ч;
   - ниже — практические занятия по 2 ч в виде «12. Практическая работа № 3. Название»: первый номер сквозной по МДК (все пары), второй — отдельная нумерация практических работ внутри МДК. Строки «В том числе практических занятий» нет. Теоретические пары подписываются только номером и названием.
6. **Видны часы по каждой теме, семестру и МДК.** Сумма по МДК равна учебному плану: отдельно теория, отдельно практика.
7. **Семестры выделены строками** («1 курс, 2 семестр — 72 ч»). После семестра с аттестацией — строка «Промежуточная аттестация: экзамен / дифференцированный зачёт / контрольная работа».
8. **Коды в правом столбце:** ПК и ОК темы и через строку ЛР, соответствующие этим ОК.
9. **Практики.** Учебная практика группируется по видам работ: у каждого вида свои часы и ПК, внутри — пары по 2 ч. Производственная — виды работ по дням.
10. **Завершение таблицы:** строка «Экзамен по модулю (семестр)» и итоговая строка «Всего» с объёмом модуля по плану.

### 1.5. Личностные результаты [СПЭТ]

- В п. 1.1.3 две таблицы:
  - соответствие ОК и ЛР **в точности по таблице 3 программы воспитания**;
  - список ЛР, которые формирует модуль, с полными формулировками.
- В модуль включаются **все** ЛР программы воспитания: соотнесённые с ОК 01–09 по таблице 3 — без отбора; не соотнесённые ни с одной ОК — отдельной строкой «Без привязки к ОК». В перечне ЛР модуля — все ЛР с формулировками. Отбор только «профессиональных» ЛР методический отдел не принимает. (В программе для этого есть параметр `"lr_subset": true` в project.json, по умолчанию он выключен.)
- Коды ЛР стоят в столбце кодов структуры (п. 2.1) и тематического плана (п. 2.2).
- В разделе 4 есть таблица оценки ЛР. ЛР не оцениваются отметкой — фиксируется «проявлено / частично / не проявлено».

### 1.6. Требования к ФОС

1. **Паспорт:**
   - показатели по каждой ПК и ОК;
   - ЛР;
   - формы аттестации по семестрам — строго по учебному плану;
   - матрица «элемент модуля × ПК»;
   - шкала 90/75/60 %.
2. **Текущий контроль:**
   - тест по каждому МДК — не меньше 15 вопросов, 4 варианта, один правильный;
   - **правильные ответы распределены равномерно по буквам а–г**;
   - перечень практических работ и критерии их оценки.
3. **Промежуточная аттестация — по каждой форме из учебного плана:**
   - экзамен или зачёт: перечень вопросов, перечень практических заданий, образец билета, критерии;
   - «ДР» (другая форма контроля): контрольная работа в двух вариантах с эталонами ответов.
4. **Практики:**
   - виды работ с ПК и часами;
   - состав отчёта;
   - критерии;
   - аттестационные листы;
   - характеристика с ОК и ЛР.
5. **Экзамен по модулю:**
   - проверяет **все** ПК модуля. Обычно это практическое задание на рабочем месте плюс защита портфолио по итогам производственной практики;
   - не меньше 4 равноценных вариантов. Сведения для экзаменатора (например, какие неисправности вносятся) помечены отдельно;
   - 100-балльный оценочный лист, критерии есть по каждой ПК. «Вид деятельности освоен» — 60 баллов и больше при не менее 50 % по каждой ПК;
   - формы протоколов.
6. **Ключи** к тестам и эталоны ответов к контрольным работам вынесены в отдельный раздел.

### 1.7. Оформление [практика]

- Times New Roman 12 пт, в таблицах 11 пт. Межстрочный интервал около 1,15, абзацный отступ 1,25 см, выравнивание по ширине.
- Поля книжной страницы: левое 30 мм, правое 15 мм, верхнее и нижнее 20 мм. Раздел 2 — альбомная ориентация с полями 20 мм.
- Номера страниц внизу по центру, на титуле номера нет.
- У длинных таблиц шапка повторяется на каждой странице.
- Литература — по ГОСТ Р 7.0.100-2018, издания не старше 5 лет, с указанием «Текст : непосредственный» или «Текст : электронный». Каждое издание сверяется с фондом библиотеки или ЭБС техникума.

### 1.8. Типичные ошибки

- Часы в программе не совпадают с учебным планом. Чаще всего ошибка в разбивке по семестрам.
- Занятия длиной 1 или 3 часа, производственная практика не кратна 6 часам.
- У темы вместо краткого содержания — повтор названия занятия.
- Сквозная нумерация через все МДК вместо нумерации внутри каждого.
- ПК переформулированы своими словами вместо текста ФГОС.
- ФОС сдан отдельным файлом.
- Нет ЛР или они не соответствуют программе воспитания текущего года.
- Правильные ответы теста стоят в основном под одной буквой.
- Выдуманная литература: несуществующие книги, неверные годы и страницы. Это особенно частая ошибка нейросетей.
- Номера страниц в содержании не совпадают с фактическими.

## Часть 2. Как составить программу вручную

1. **Соберите исходные данные:**
   - учебный план группы (строки ПМ, его МДК, УП, ПП: часы теории и практики по семестрам, формы аттестации);
   - ФГОС (ОК, ПК модуля);
   - ПОП;
   - профстандарт;
   - программу воспитания (ЛР и таблицу 3).
2. **Распределите часы.** Для каждого МДК по семестрам: сколько пар теории и сколько часов практики. Сумма по семестру равна плану, сумма теории и практики по МДК — тоже. Курсовой проект, если он есть, ставится в последний семестр МДК.
3. **Составьте темы.** Для каждой: название, краткое содержание, теоретические пары, практические занятия с часами, коды ПК и ОК. Проверьте суммы.
4. **Учебная практика:** виды работ с ПК, внутри — задания парами.
5. **Производственная практика:** виды работ по дням по 6 ч. Первый день — инструктаж, последние — отчёт и зачёт. Все ПК модуля должны встретиться.
6. **Раздел 1:** навыки, умения, знания (из ПОП), критерии по ПК и ОК.
7. **Раздел 3:** помещения и оснащение (по паспортам лабораторий), ПО, литература.
8. **ФОС:** тесты, вопросы и задания, контрольные работы, экзамен по модулю, формы.
9. **Сведите всё в один файл** по структуре из п. 1.3 и пройдите проверочный лист из части 4.

На практике пункты 2–9 занимают много дней. Программа `rpgen` выполняет пункты 2 и 9 автоматически, а пункты 3–8 поручает нейросети и проверяет её ответы.

## Часть 3. Программа rpgen

### 3.1. Как устроена программа

```
учебный план (TSV) ─┐
ФГОС (JSON) ────────┼─► init ─► каркас content.json ─► fill / next+import ─► content.json ─► validate ─► build ─► .docx
программа воспитания ┘          (часы, семестры, формы)    (нейросеть пишет тексты)                       (РП + ФОС одним файлом)
```

- **Структуру строит программа:** часы, семестры, пары, дни практики, формы аттестации, нумерацию, ЛР, оформление, содержание с номерами страниц. Нейросеть их **не трогает**.
- **Наполнение пишет нейросеть по этапам:** темы и занятия, виды работ, навыки и умения, критерии, литература, тесты, вопросы, задания, экзамен.
- **Каждый ответ проверяется:** суммы часов, количество занятий, коды ПК, формат тестов, баллы оценочного листа. Если проверка не пройдена, нейросеть получает список замечаний и переделывает ответ (до 4 попыток).

### 3.2. Установка

1. Установите **Node.js 18 или новее** (nodejs.org).
2. Распакуйте папку `rpgen`, откройте в ней терминал и выполните:
   ```
   npm install
   ```
3. Для автоматической расстановки номеров страниц в содержании нужен **LibreOffice** и утилита `pdftotext` (пакет poppler).
   - **Linux:** `sudo apt install libreoffice poppler-utils`.
   - **Windows:** LibreOffice устанавливается обычным инсталлятором; poppler для Windows скачивается отдельно, путь к `pdftotext.exe` добавляется в PATH.

   Без них документ тоже соберётся, но номера страниц в содержании нужно будет проставить вручную.

### 3.3. Подготовка учебного плана

1. Откройте учебный план в Excel.
2. Выделите таблицу от шапки до последней строки и скопируйте.
3. Вставьте в Блокнот и сохраните как `data/plans/ГРУППА.tsv` в кодировке UTF-8.

Столбцы должны идти в таком порядке:

`Индекс | Наименование | Формы ПА | Максимальная | Самостоятельная | Обязательная | Теория | Практика | Курсовых | семестр 1 | семестр 2 | …`

Формы аттестации пишутся через запятую — по одной на каждый семестр, где есть часы: `-, -, Э`. Обозначения: Э, ДЗ, З, ДР, КР.

### 3.4. Новый документ — пошагово

```
node src/cli.js new projects/PM02_OA-2401 --plan data/plans/OA-2401.tsv --pm ПМ.02 --vd "Организация сетевого администрирования операционных систем"
```

Откройте `projects/PM02_OA-2401/project.json` и проверьте поля:

| Поле | Что указать |
|---|---|
| `org` | министерство, тип и наименование, краткое название, город, ПЦК, кто утверждает |
| `people` | разработчик, эксперт от работодателя |
| `year`, `group`, `form` | год, группа, форма обучения |
| `pop_reg_number` | регистрационный номер ПОП |
| `vd_name` | для ПМ.03 (вид деятельности по выбору) — точное название выбранного ВД из ФГОС |
| `course_offset` | 0, если 1-й столбец плана — 1 курс; 1, если план начинается со 2 курса |
| `hints.general` | пожелания к содержанию: оборудование, ПО, акценты. Например: «в лаборатории коммутаторы Eltex и маршрутизаторы Cisco, эмулятор Packet Tracer; учесть требования WorldSkills / Профессионалитета» |
| `hints.mdk` | пожелания по конкретным МДК: `{"МДК.02.01": "Astra Linux и Windows Server"}` |
| `hints.up` | пожелания по учебной практике |
| `llm` | подключение к нейросети (см. п. 3.5) |

Затем выполните:

```
node src/cli.js init projects/PM02_OA-2401/project.json
```

Программа разберёт план и покажет разбивку: семестры, пары теории, часы практики, курсовой проект, дни производственной практики. Если план содержит ошибки (часы не делятся на пары, сумма не сходится), она перечислит их. **Исправьте учебный план до продолжения.**

### 3.5. Наполнение через API нейросети (автоматический режим)

Раздел `llm` в `project.json`:

```json
"llm": { "provider": "openai", "base_url": "…", "model": "…", "api_key_env": "LLM_API_KEY", "temperature": 0.4, "json_mode": true }
```

| Сервис | provider | base_url |
|---|---|---|
| OpenAI | openai | https://api.openai.com/v1 |
| Qwen (Alibaba Cloud DashScope) | openai | https://dashscope.aliyuncs.com/compatible-mode/v1 (международный — https://dashscope-intl.aliyuncs.com/compatible-mode/v1) |
| DeepSeek, OpenRouter и другие OpenAI-совместимые | openai | адрес из документации сервиса |
| Локальная модель через Ollama | openai | http://localhost:11434/v1 |
| Локальная модель через LM Studio | openai | http://localhost:1234/v1 |
| Claude (Anthropic) | anthropic | https://api.anthropic.com/v1 |

- `model` — идентификатор модели из документации сервиса.
- Ключ API **не пишите в файл.** Задайте переменную окружения:
  - Windows: `set LLM_API_KEY=ключ`;
  - Linux/macOS: `export LLM_API_KEY=ключ`.
- Если локальная модель не поддерживает режим JSON, поставьте `"json_mode": false`.
- Слабые модели (меньше примерно 30 млрд параметров) часто не попадают в бюджет часов. Выбирайте модель уровня Qwen-Plus/Max, DeepSeek-V3, GPT-4 или Claude.

Запуск:

```
node src/cli.js stages projects/PM02_OA-2401/project.json   # список этапов
node src/cli.js fill   projects/PM02_OA-2401/project.json   # выполнить все невыполненные
```

Этапы выполняются по порядку:

1. `program` — навыки, умения, знания, критерии по ПК и ОК, место модуля.
2. `themes:МДК:N` — темы и занятия каждого МДК по семестрам. Каждый следующий семестр видит темы предыдущих.
3. `course:МДК` — курсовой проект, если есть.
4. `up:N` — учебная практика по семестрам.
5. `pp:N` — производственная практика по семестрам.
6. `conditions` — помещения, ПО, литература.
7. `tests:МДК`, `exam:МДК`, `cw:МДК` — тесты, вопросы и задания, контрольные работы.
8. `module_exam` — экзамен по модулю.

После каждого этапа результат сохраняется в `content.json`. Если работа прервалась, просто запустите `fill` снова — продолжится с того же места.

Переделать отдельный этап:

```
node src/cli.js fill project.json --only themes:МДК.02.01:2 --redo
node src/cli.js fill project.json --only tests --redo        # все тесты
```

Если переделали темы МДК, переделайте и зависящие от них этапы: `up`, `tests`, `exam`, `cw` этого МДК.

### 3.6. Ручной режим (без API, через обычный чат)

Подходит, если есть только чат-версия нейросети: ChatGPT, Qwen Chat, GigaChat, Алиса, Claude и т. п.

```
node src/cli.js next project.json
```

1. Программа запишет промпт следующего этапа в `prompt_next.md`. Скопируйте его **целиком** в чат.
2. Ответ нейросети (JSON) сохраните в файл, например `answer.json`.
3. Выполните:
   ```
   node src/cli.js import project.json answer.json
   ```
4. Если ответ не прошёл проверку, программа выведет готовое сообщение с замечаниями. Отправьте его в тот же чат, сохраните новый ответ и повторите `import`.
5. Повторяйте `next` → чат → `import`, пока этапы не закончатся.

Совет: каждый этап удобнее начинать в новом чате, чтобы нейросеть не путала этапы.

### 3.7. Проверка, правка и сборка

```
node src/cli.js validate project.json   # ошибки блокируют сборку, предупреждения — нет
node src/cli.js build project.json      # готовый .docx (путь — в поле output)
```

**Правка вручную.** `content.json` — обычный текстовый файл, его можно править в любом редакторе (удобно в VS Code). Что где лежит:

| Что | Где в content.json |
|---|---|
| Темы | `mdk[i].blocks[j].themes[k]`: `name`, `summary` (краткое содержание), `theory` (пары), `practice` (`[название, часы]`), `codes` |
| Учебная практика | `up[i].works[k].tasks` |
| Производственная практика | `pp[i].works[k].days` |
| Общая часть программы | `program` |
| ФОС | `fos` |

Часы в каркасе (`T`, `P`, `hours`) менять нельзя: они взяты из учебного плана. Если поменяли что-то в темах, запустите `validate`.

**Особые случаи сборки:**

- `build --force` — собрать, несмотря на ошибки (например, чтобы посмотреть черновик). Такой документ **сдавать нельзя**.
- `build --no-toc` — не считать номера страниц (быстрее).

### 3.8. Перенастройка под другие условия

- **Другая специальность:** создайте `data/fgos/КОД.json` по образцу `09.02.06.json`. ОК и ПК копируются **дословно** из ФГОС, вкладка «таблица № 2».
- **Новый учебный год:** сделайте копию `data/vospitanie/spet_2026-2027.json` и обновите:
  - `lr` — формулировки ЛР;
  - `ok_lr` — соответствие ОК и ЛР по таблице 3;
  - `ok_lr_module` — какие ЛР модуль формирует напрямую.

  В `project.json` укажите новый файл.
- **Свой стиль формулировок:** правьте промпты в папке `prompts/`: `system.md` — общие правила, остальные файлы — по этапам. Переменные в фигурных скобках `{{…}}` подставляет программа — их не удаляйте.
- **Другие тексты шаблона** (пункты оборота титула, стандартные абзацы разделов 3–4, критерии оценок) — в `src/build.js`.

### 3.9. Что обязательно проверяет человек

Программа гарантирует структуру и арифметику, но не достоверность фактов. Перед сдачей преподаватель обязан проверить:

1. **Литературу.** Каждое издание найти в ЭБС или каталоге библиотеки и исправить выходные данные. Пометки «[проверить]» удалить.
2. **ГОСТы и нормативные документы**, на которые есть ссылки в темах и списках.
3. **Ключи тестов и эталоны ответов.** Решить каждый расчётный вопрос самому.
4. **Экзамен по модулю.** Задания должны быть выполнимы на реальном оборудовании лаборатории за отведённое время. Неисправности для экзаменатора должны действительно воспроизводиться.
5. **Помещения и оснащение** — по паспортам кабинетов и лабораторий.
6. **Трудовые функции профстандарта** (столбец «ТФ ПС»), если нейросеть их заполнила.
7. **Реквизиты:** Ф. И. О., номер ПОП, год, город.

### 3.10. Если что-то пошло не так

| Сообщение | Причина и решение |
|---|---|
| «В учебном плане не найден модуль» | В TSV индекс записан иначе (например, «ПМ 01»). Исправьте на «ПМ.01» |
| «часы … не делятся на пары» | В плане нечётные часы. Согласуйте исправление плана с учебной частью |
| «Нейросеть не дала корректный ответ за 4 попытки» | Модель слабая или этап слишком большой. Возьмите модель сильнее, уменьшите `temperature`, увеличьте `--attempts 6` или выполните этап в ручном режиме |
| `LLM API 401/403` | Неверный ключ или не задана переменная окружения |
| «LibreOffice или pdftotext не найдены» | Установите их (п. 3.2) или проставьте номера страниц в содержании вручную |
