# Для агентов (Claude, Codex, Qwen и др.)

Задача репозитория — рабочая программа профессионального модуля СПО + ФОС одним .docx по шаблону ГБПОУ «СПЭТ».

1. Прочитай `ИНСТРУКЦИЯ.md` целиком (часть 1 — правила документа, часть 3 — программа).
2. Оформление делает только программа (`src/build.js`). Не собирай .docx вручную и не меняй структуру через другие инструменты — иначе оформление разойдётся с примером.
3. Порядок: `tools/plan_from_xlsx.py` (план .xlsx → TSV), `tools/pop_extract.py` (ПОП 2025) или `tools/pop_extract_2021.py` (ПООП 2021, напр. 09.02.07) → `data/pop/*.json` → `node src/cli.js new` → `init` → `fill` или `next`/`import` → `validate` → `build`.
4. Нельзя: менять темы, содержание тем, лабораторные работы и виды работ практик ПОП; менять часы учебного плана; ставить зачёт производственной практике; упоминать портфолио, WorldSkills, таблицу «Цифровые инструменты».
5. Эталоны: `examples/PM01_OA-2401/`, `PM03_OA-2401/` (МДК из готовой программы, курсовой), `PM05_OP-2301is/`, `PM06_OP-2301is/` (ПООП 2021);
   основной эталон — `examples/PM01_OA-2401/` (`project.json`, `content.json`, готовый .docx). Сборка примера должна давать байт-в-байт тот же `word/document.xml`.
6. После `init` проверь замечания: коды МДК в файле ПОП должны совпадать с учебным планом; если практических пар в плане меньше, чем лабораторных работ ПОП, соседние работы одной темы объединяются автоматически.
7. Новая специальность: создай `data/fgos/КОД.json` по образцу существующих (ОК, ПК дословно из ФГОС/ПОП); если ОК не 01–09 — `ok_lr_override` в `project.json`. МДК, который надо взять из готовой программы, задаётся как `custom: true` с `lessons` (образец — МДК.03.01 в `examples/PM03_OA-2401/content.json`).
8. После изменений в `src/` или `prompts/` запусти `node tools/selftest.js` — должно быть «Самопроверка пройдена».
